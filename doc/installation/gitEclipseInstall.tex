\section{Overview}

This document describes how to install ArtiSynth directly from GitHub
and import it into the Eclipse IDE (Integrated Development
Environment), within a \SYSTEM{} environment. While for demonstration
purposes it is faster to install ArtiSynth using a precompiled
release, installing from GitHub provides access to the most recent
updates, and the Eclipse IDE is a convenient platform for developing
and modifying the Java code used to create ArtiSynth models.

There are two parts to the installation process:

\begin{enumerate}

\item Installing Eclipse

\item Installing ArtiSynth from GitHub

\end{enumerate}

Eclipse comes with its own version of Java, which is sufficient for
compiling and running ArtiSynth within Eclipse, so you do not need to
install Java separately. A separate Java development kit (JDK) is
needed only in special cases, as described in Section
\ref{JavaRequirements:sec}.

This document is intentionally brief and describes only installation
from Git into an Eclipse IDE. More complete instructions,
including how to create and add models, integrate external
models, and update ArtiSynth, are given in the general
\ifLinux
\artisynthManual[installation/linuxInstallation]{linuxInstallation}%
{Installation Guide}.
\fi
\ifWindows
\artisynthManual[installation/windowsInstallation]{windowsInstallation}%
{Installation Guide}.
\fi
\ifMacOS
\artisynthManual[installation/macosInstallation]{macosInstallation}%
{Installation Guide}.
\fi
Instructions for visualizing, navigating, editing
and simulating models are given in the
\artisynthManual{uiguide}{ArtiSynth User Interface Guide}.
Instructions on how to {\it build} a model using Java are given in
the \artisynthManual{modelguide}{ArtiSynth Modeling Guide}.

\section{System Requirements}
\label{SystemRequirements:sec}

\ifMacOS
ArtiSynth runs on Macs based on either Apple silicon (the Apple M
chips) or Intel processors.
\else
Your host machine should be a 64-bit system based on an Intel or AMD
processor (often referred to as {\tt x86\_64}, {\tt x64} or {\tt
amd64}).
\fi
%
We recommend a minimum of 16 Gbytes of memory, and more is better if
you are doing finite element work with larger numbers of elements.

\subsection{Java requirements}
\label{JavaRequirements:sec}

You should use Java 21 or later. While ArtiSynth is currently
compiled to be compatible with Java 8, this will be raised to Java 21
in the near future. The version of Java that comes with Eclipse (Java
21 or later for Eclipse 2024-09 and newer) meets this recommendation and
is used by default to compile and run ArtiSynth.

You will need to install a separate Java development kit (JDK) only if
\begin{itemize}

\item you want to compile or run ArtiSynth from a terminal window,
outside of Eclipse; or

\item you need a specific version of Java. In particular, if you plan
to use ArtiSynth with MATLAB, ArtiSynth should be run with Java 21,
which is compatible with recent versions of MATLAB (see
\artisynthManual{matlab}{Interfacing ArtiSynth to MATLAB}), whereas
newer versions of Eclipse come with later versions of Java.

\end{itemize}
If either of these apply, see Section \ref{InstallingJDK:sec}.

\section{Installing Eclipse}

Eclipse is an integrated development environment (IDE) that is
commonly used for writing and maintaining Java programs. While other
IDEs exist for Java, such as IntelliJ and VS Code, Eclipse is
currently the most commonly used amongst ArtiSynth users. It should be
noted, however, that an IDE is not {\it required} for Java
programming; simpler programs, in particular, can often be created by
editing the {\tt .java} source files using a text editor and then
compiling them with command line tools, including GNU {\tt make}, if
that is available, or the {\tt compile} utility supplied by ArtiSynth.

Eclipse is released quarterly, with versions named by year and month
(e.g., {\tt 2026-09}). Any recent version should work; the
instructions below use {\tt 2026-09} as an example.

\section{Installing ArtiSynth}

\begin{enumerate}

\item From the panel at the left of the main Eclipse frame, choose
``{\sf Import projects...}''. This will cause an {\sf Import} dialog to
appear, as shown below. Open ``{\sf Git > Projects from Git}'', and then
click {\sf Next}.

\fi
\end{center}

\item In the next dialog, choose {\sf Clone URI}, and click {\sf Next}.

\item A {\sf Source Git Repository} dialog will appear, as shown
below. In the {\sf URI} field at the top, enter\\{\tt
https://github.com/artisynth/artisynth\_core.git}\\This will
automatically fill the {\sf Host} and {\sf Repository path} fields.
Click {\sf Next}.

\item A {\sf Local Destination} dialog will appear, as shown below,
indicating the \directory{} into which ArtiSynth will be placed locally. Use
the default location, or edit it to some other desired location.  This
will be your {\it ArtiSynth installation \directory{}}.
Click {\sf Next}.

\begin{center}

\section{Updating ArtiSynth}

To update ArtiSynth to the latest version on GitHub, right-click on
{\tt artisynth\_core} in the Package Explorer and choose {\sf Team >
Pull}. If the update requires new or different libraries, they are
downloaded automatically the next time Eclipse builds the project, as
during installation, and libraries that are no longer needed are
removed.

The pull may be refused if it would overwrite files that you have
modified locally, such as {\tt ArtiSynth.launch} or {\tt .classpath}.
Eclipse will then report an error, and clicking {\sf Details} in the
error dialog lists the files concerned. Information on resolving
this is given in the Section ``Refused pulls'' in the general
\ifLinux

\section{Installing a Separate JDK (Optional)}
\label{InstallingJDK:sec}

As described in Section \ref{JavaRequirements:sec}, you need a
separate JDK only to compile or run ArtiSynth from a terminal window,
or to use a specific version of Java (such as Java 21 for use with
MATLAB). Any JDK of version 21 or later will work. Free builds of the
JDK are available from several sources; we suggest Eclipse Temurin,
available from

\href{https://adoptium.net/temurin/releases/}%
{adoptium.net/temurin/releases}.

\begin{sideblock}
JDKs are also available from Oracle at 
\href{https://www.oracle.com/java/technologies/downloads/}%
{www.oracle.com/java/technologies/downloads} 
but may be subject to certain licensing restrictions.
\end{sideblock}

Select your operating system and architecture, the package type {\sf
JDK}, and the desired version (21, or later).
\ifWindows
For \SYSTEM{}, choose the architecture {\sf x64}; the easiest option
is then the {\tt .msi} installer.
\fi
\ifMacOS
For \SYSTEM{}, choose the architecture {\sf aarch64} if your Mac uses
Apple silicon, or {\sf x64} if it uses an Intel processor. The easiest
option is then the {\tt .pkg} installer.
\fi
\ifLinux
For \SYSTEM{}, choose the architecture {\sf x64}, and then unpack the
{\tt .tar.gz} archive into a location of your choice, such as {\tt
/opt/java}. This will create the JDK home \directory{}, with a name like
{\tt /opt/java/jdk-21.0.8+9}.  Many Linux distributions also provide JDKs
as packages (e.g., {\tt openjdk-21-jdk} on Ubuntu), which will install
into locations such as {\tt /usr/lib/jvm/java-21-openjdk-amd64}.
\fi

\ifWindows
The home \directory{} for a JDK install is usually something like 
\begin{verbatim}
 C:\Program Files\Eclipse Adoptium\jdk-21.0.8.9-hotspot
\end{verbatim}
for Temurin and 
\begin{verbatim}
  C:\Program Files\Java\jdk-21
\end{verbatim}
for Oracle.
\fi
\ifMacOS
The home \directory{} for a JDK install is usually something like 
\begin{verbatim}
  /Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home
\end{verbatim}
for Temurin and 
\begin{verbatim}
  /Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home
\end{verbatim}
for Oracle.
\fi

\ifMacOS
\begin{sideblock}
Previous versions of these instructions asked that an Intel-based
({\sf x64}) JDK be installed on Macs with Apple silicon, so that

\end{sideblock}

\subsection{Making the JDK visible from a terminal window}
\label{MakingJDKVisible:sec}

To compile or run ArtiSynth from a terminal window, the {\tt java} and
{\tt javac} commands of your JDK must be visible there. To check this,
open a terminal window, run the command {\tt javac -version}, and check
that the command is found and that the version matches your JDK.
\ifWindows
The JDK installer usually takes care of this. If it has not,
you can fix this by adding
{\tt <JDK\_HOME>\BKS bin} to your Path, where
{\tt <JDK\_HOME>} is the home \directory{} for your JDK
as described in Section \ref{InstallingJDK:sec},
making sure it is {\it ahead} of any other
Java installations that might be specified on the Path.

The Path is a list of directories which the system searches in
order to find executables. You can add {\tt <JDK\_HOME>\BKS bin}
to it as follows:

\begin{enumerate}

\item Open the {\sf Start} search, enter ``{\tt env}'', and choose
{\sf ``Edit the system environment variables''}.

\item Click on {\sf Environment Variables}.

\item Under {\sf User variables} (the top window), click on {\sf Path}
and click {\sf Edit}. If {\sf Path} does not exist, click {\sf New}.

\item In the {\sf Edit environment variable} dialog, click {\sf New}
and enter {\tt<JDK\_HOME>\BKS bin}. Use {\sf Move Up} to place it
ahead of any other Java entries.

\item Close {\it all} dialogs by clicking {\sf OK} and restart
any terminal windows.

\end{enumerate}
\fi
\ifMacOS
If it does not, or if you have several JDKs installed,
you can set the ``default'' JDK by setting the {\tt JAVA\_HOME}
environment variable.  This can be done inside the
initialization file for your command line shell.
Assume that the desired JDK has version number {\tt 21} and
that your home \directory{} is {\tt <HOMEDIR>}.

\begin{itemize}

\item If your command line shell is {\tt zsh} (which it will be by
default), then the initialization file is {\tt <HOMEDIR>/.zshrc}. Use a
plain text editor to edit (or create) this file and insert a line of
the form
%
\begin{lstlisting}[]
  export JAVA_HOME=`/usr/libexec/java_home -v 21`
\end{lstlisting}
%
The same line can be used if your shell is {\tt bash}, in which case
the initialization file is {\tt <HOMEDIR>/.bashrc}.

\item If you have changed your shell to {\tt csh} or {\tt tcsh},
then the initialization file is {\tt <HOMEDIR>/.cshrc}. Use a plain text editor
to edit or create this file and insert a line of the form
%
\begin{lstlisting}[]
  setenv JAVA_HOME `/usr/libexec/java_home -v 21`
\end{lstlisting}
%

\end{itemize}

Note that in both examples above, the left quote character "{\tt \`{}}" is used
instead of the more common right quote "{\tt '}".

Setting {\tt JAVA\_HOME} can also be done directly within the shell;
doing it within the initialization file simply avoids the need to do
so each time a new terminal window is opened.
\fi
\ifLinux
If it does not, one fix is to add the \directory{} {\tt <JDK\_HOME>\SEP
bin} to your system {\tt PATH} variable, where {\tt <JDK\_HOME>} is the
installation \directory{} for your JDK (Section \ref{InstallingJDK:sec}).
In particular, {\tt
<JDK\_HOME>\SEP bin} should be added {\it ahead} of any other Java
installations that might be specified on the {\tt PATH}.  If you are
using the {\tt bash} shell, then modifications to {\tt PATH} can be
made inside a {\tt .bashrc} file located in your home directory.
For example, if {\tt <JDK\_HOME>} is {\tt /opt/java/jdk-21.0.8+9},
then you can add the line
\begin{verbatim}
export PATH="/opt/java/jdk-21.0.8+9/bin:$PATH"
\end{verbatim}
to your {\tt .bashrc}. To see the current contents of the {\tt PATH},
open a terminal window and run the command
\begin{verbatim}
 > echo $PATH
\end{verbatim}
\fi
